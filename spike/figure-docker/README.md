# Spike: regenerate a paper's figure in Docker

> **This is a throwaway spike, not reCRATE.** Every path, chunk and package here is
> pinned to one paper. It exists to show the idea works end to end, and to tell
> Milestone 4 what it is really up against. Keeping any of it is a new decision.

## What it shows

reCRATE's figure story is: **a figure is reproduced by running the authors' own
code, at their own pinned versions, on their own shared data — and a person
decides whether the result matches.** This demonstrates exactly that, for one
figure, in about two commands.

```bash
./run.sh
```

It clones [Lee-V-Jones/Reproducibility](https://github.com/Lee-V-Jones/Reproducibility)
at commit `370e615`, builds an image with **R 4.4.2** — the version the paper's own
`Inferential_session_info.txt` records — runs the authors' plotting code unchanged,
and puts the regenerated swimmer plot beside the one they published.

## Why the swimmer plot

Of the paper's figures, it is the one that is genuinely reproducible from what was
shared:

| Figure | Reproducible? |
|---|---|
| `swimmerB` | **Yes** — built by `ggplot` from `data/model_data_long_with_dictionary.xlsx`, which is in the repo, and the authors committed their rendered `figures/swimmerB.png` to compare against |
| `p1`, `p2` | Generated by code, but never committed — so there is no published image to compare with |
| MCMC diagnostic | Needs `brms` + Stan: hours of C++ compilation |
| `myflow`, `flowinferential` | Hand-drawn; no generating code exists. Their N counts are checkable as *numbers* instead |

## What it deliberately does not do

- **No Stan.** The swimmer plot needs no model fit, so `brms`/`rstan` are left out
  and the image builds in minutes instead of hours.
- **No full Quarto render.** Rendering the whole `.qmd` would fit the Bayesian model
  first. Only the chunks the figure depends on are extracted.
- **No automated match verdict.** The script reports the machine facts — the run
  succeeded, the file was produced — and stops. Whether the figures *match* is a
  person's call, recorded as such. There is no pixel diff and no similarity score.

## What Milestone 4 has to solve that this dodges

1. **Chunk extraction is manual here.** The real thing must work out, from any
   `.qmd`, which chunks a given figure depends on.
2. **Package pinning is loose here.** `rocker/r-ver:4.4.2` gives a date-matched
   snapshot; the session info names exact versions (ggplot2 4.0.1, dplyr 1.1.4, …)
   that a real build should honour.
3. **`--platform linux/amd64`** is forced so prebuilt package binaries are used.
   On Apple Silicon that means emulation.
4. **The published PNG was not produced by the committed code** — the script
   `ggsave`s an EPS. So "identical" was never achievable; "visually the same
   figure" is the honest bar, which is precisely why the verdict is a person's.
